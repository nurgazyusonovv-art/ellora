# Сабактын JSON форматы

Сабактын мазмуну `lessons.content` талаасында JSON болуп сакталат. TypeScript түрлөрү: `src/lib/lesson-types.ts`
(бул файл — бирдиктүү булак; айырма болсо, коддун айтканы туура). Толук мисалдар: `src/content/lessons/` (китепкана — `src/content/index.ts`).

```jsonc
{
  "version": 1,
  "duration": 45,            // милдеттүү эмес: сабактын жалпы узактыгы (мүнөт), жок болсо 45
  "stages": [
    // ар дайым 5 бөлүк, ушул тартипте:
    { "key": "discover",  "title": "...", "intro": "...", "minutes": 5,  "blocks": [ ... ] },
    { "key": "learning",  "title": "...", "minutes": 10, "blocks": [ ... ] },
    { "key": "practice",  "title": "...", "minutes": 15, "blocks": [ ... ] },
    { "key": "reinforce", "title": "...", "minutes": 7,  "blocks": [ ... ] },
    { "key": "exit",      "title": "...", "minutes": 3,  "blocks": [ ... ] }
  ]
}
```

`duration` мугалимге гана керек: конструктор бөлүктөрдүн `minutes` суммасын ушуга салыштырып көрсөтөт.

Ар бир блоктун сабак ичинде уникалдуу `id`'си болот (мисалы `p2`). Жооптор `answers.block_id` аркылуу ушул id'ге байланат,
ошондуктан **жарыяланган сабактагы блоктун id'син өзгөртпө**.

Тексттерде `**калың**` жана `` `код` `` белгилери иштейт, абзацтар бош сап (`\n\n`) менен бөлүнөт.

## Блок түрлөрү

| type | Талаалар | Бааланабы | Эскертүү |
| --- | --- | --- | --- |
| `investigation` | `prompt`, `procedure`, `code?`, `simulation?` | жок | Божомол → сынап көрүү → байкоо → жыйынтык; божомол биринчи сакталат |
| `text` | `body`, `title?` | жок | |
| `code_example` | `code`, `caption?`, `runnable?` | жок | `runnable: true` — окуучу өзгөртүп иштете алат |
| `mcq` | `prompt`, `options[]`, `correct` (индекс), `code?`, `mono?`, `explain?`, `hint?`, `xp?` | ооба | Exit ticket'те бир гана аракет |
| `code_task` | `prompt`, `starter`, `tests[{input, expected}]`, `hint?`, `xp?` | ооба | stdin → stdout; бардык тесттер өтсө туура |
| `parsons` | `prompt`, `lines[]` (туура тартипте), `xp?` | ооба | Саптар аралаштырылып көрсөтүлөт |
| `bug_hunt` | `prompt`, `code`, `bugs[{line, explain}]`, `fixed?`, `xp?` | ооба | `line` 1ден башталат |
| `open` | `prompt`, `placeholder?`, `optional?`, `feedback?`, `feedbackCode?`, `compareTo?`, `rubric?`, `lockOnSubmit?`, `engagement?` | жок | `feedback` жооптон кийин көрсөтүлөт |
| `confidence` | `prompt` | жок | 1–4 шкала; exit ticket үчүн |

## Бөлүктү бүтүрүү эрежеси

- Бааланган блоктор (`mcq`, `code_task`, `parsons`, `bug_hunt`) туура аткарылышы керек.
- `open` (милдеттүү) жана `confidence` — жооп берилсе жетиштүү. `optional: true` болсо талап кылынбайт.
- Интерактивдүү блогу жок бөлүк «Түшүндүм, улантуу» баскычы менен бүтөт.
- Exit ticket'те туура/туура эмес талап кылынбайт, окуучу «Билетти тапшыруу» баскычын басат.
  `exit_score` = туура жооп берилген `mcq` саны, `exit_total` = бардык `mcq` саны.

Бул эрежелер серверде текшерилет: `src/lib/grading.ts` (баалоо, бөлүк, XP) жана `src/app/actions/student.ts`.
Ойноткуч жоопту дароо көрсөтөт, бирок XP, ачылган бөлүк жана натыйжа серверден келет.
Окуучуга сабак жашырылган түрдө жөнөтүлөт (`src/lib/student-view.ts`): `mcq.correct` = -1, `parsons` саптары
аралаштырылган (`shuffled: true`), `bug_hunt`та табылган каталар гана (`bugCount` — жалпы саны). Блок чечилгенде
сервер анын ачык көрүнүшүн кайтарат.

## XP

Ар бир бааланган блок биринчи жолу туура аткарылганда `xp` (адатта 10) кошулат. Exit ticket'ти тапшырганда +20.

## Жаңы блок түрүн кошуу

1. `src/lib/lesson-types.ts` — түрүн кош, `Block` union'уна жаз, `isGraded`/`isInteractive` текшер.
2. `src/components/player/blocks.tsx` — компонент (`Props<B>`: `block`, `saved`, `onAnswer`).
3. `src/components/player/lesson-player.tsx` — `renderBlock` ичине case кош.
4. `src/app/teacher/lessons/[id]/page.tsx` — `BLOCK_LABELS`ке аталышын кош.
5. Бул файлдагы таблицаны жаңырт.

## 5E модели (жаңы сабактар)

`model: "5e"`, `objectives: string[]`, `successCriteria: string[]`, `teacherNotes?: string` кошулат.
Базадагы `key` тартиби ошол бойдон, бирок 5E сабакта мааниси төмөнкүдөй:

| key | 5E бөлүгү | Милдеттүү окуу далили |
| --- | --- | --- |
| discover | Кызыктыруу (Engage) | `open` + `lockOnSubmit: true`: баштапкы ой |
| learning | Изилдөө (Explore) | `investigation`: божомол, байкоо, жыйынтык; туура жоопту талап кылган тест жок |
| practice | Түшүндүрүү (Explain) | Окуучунун өз сөзү менен `open` жообу, андан кийин түшүндүрмө |
| reinforce | Колдонуу (Elaborate) | Жаңы кырдаалда `code_task` же `rubric` менен ачык жооп |
| exit | Баалоо (Evaluate) | Тест жана `compareTo` менен баштапкы ойго кайрылган рефлексия |

`model` жок эски сабактар мурдагы маанисин сактайт. Даяр үч сабактын жаңы көчүрмөлөрү 5E; базада мурда сакталган сабактар автоматтык өзгөрбөйт.

Ар бир блокто `support?: string`, `extension?: string`, `collaboration?: "individual" | "pair" | "group"` болот. Жуп/топ талкуусу үчүн нускама берилет; ар бир окуучу жеке жооп сактайт.
`open.rubric` — мугалим белгилеген критерийлер. `compareTo` биринчи бөлүктөгү ачык жооптун id’си. `lockOnSubmit` биринчи жоопту өзгөртүүгө жол бербейт.
Изилдөөнүн `response` талаалары: `prediction`, `observations`, `conclusion`. Алгач `{phase:"prediction", prediction}` сакталат; андан кийин биринчи божомол өзгөрбөй, байкоо жана жыйынтык кошулат. Баа же XP коюлбайт.

Мугалимдин нускамасы окуучуга берилбейт. Тесттин упайы жалпы өздөштүрүүнүн далили катары каралбайт: мугалим түшүндүрүү, колдонуу жана рефлексияны критерийлер менен өзүнчө баалайт.

Жандуу сабак: `lesson_sessions.max_stage` 0–4 жана `paused` серверде текшерилет. Таблицада сап жок болсо өз алдынча режим. Окуучунун бетиндеги абал 20 секунд сайын жаңыланат. Баалоо `answer_reviews` таблицасына сакталат; окуучу өз пикирин гана көрөт.

## Жуптук жана топтук тапшырманын деталдары

`collaboration: "pair" | "group"` болгон блокко `teamwork` кошсо болот:

```json
{"size":4,"instructions":"Ролдорду бөлүштүрүп, мисалдарды салыштыргыла.","roles":["Уюштуруучу","Изилдөөчү","Жазуучу","Баяндамачы"],"outcome":"Далилдүү жалпы чечим"}
```

Жупта `size=2`, топто 3–6. Ролдордун саны катышуучуларга дал келет. Жардам жана критерийлер ошол блокко кошулат. Эски `collaboration` талаасы гана бар сабактар иштей берет. Бул класста бирге иштөө үчүн: окуучулар жалпы продукт даярдап, ар бири жеке жоопто чечимди жана өз салымын сактайт. Жооптор учурдагы `answers` аркылуу сакталат.

ЖИ конструктору сабактын `id`’лерин жана бөлүк убактысын серверде түзөт, баштапкы ойду бекитет, рефлексияны ага байланыштырат. Жуп тапшырмасы Изилдөөдө, топ тапшырмасы Колдонууда, Баалоо жеке болот. Натыйжа текшерилип, `status=draft` менен гана сакталат.

## Кызыктыруу: жөнөкөйдөн татаалга

Бир бөлүктө бир нече `open` суроо же кызыктуу тапшырма болот. Ар бирине өзүнчө жооп сакталат.
`engagement: {"level": 1, "kind": "question"}` талаасы милдеттүү эмес: level 1 — жөнөкөй эстөө/байкоо,
2 — салыштыруу/чакан аракет, 3 — божомол жана негиздөө. `kind` — `question` же `activity`.
Деңгээл белгиленген блоктор бөлүктө өсүүчү иретте жайгашат; конструктор тескери иретти жарыялоого өткөрбөйт.
Конструктордогу «Үч кадамдуу үлгү кошуу» учурдагы блокторду сактап, уникалдуу id менен үч милдеттүү,
баштапкы жоопту бекиткен ачык тапшырма кошот. Мугалим текстин темага ылайыктап өзгөртөт.
Окуучу деңгээлди жана тапшырманын түрүн көрөт; жооп туура/туура эмес деп бааланбайт.
ЖИ 3–5 кадам түзөт: үч деңгээл тең, кеминде бир суроо жана бир кызыктуу тапшырма. Рефлексия `d1` баштапкы оюна байланышат.
Эски бир суроолуу сабактар жарактуу бойдон калат; базадагы сабактар автоматтык өзгөрбөйт.

## Көндүм тегдери

Ар бир жооп талап кылган блокко `skills?: SkillId[]` кошулат (кайталанбаган, үчкө чейин).
Тизме `src/lib/skills.ts`: algorithm, logic, conditions, loops, variables, debugging, testing, explanation.
Бул талаа милдеттүү эмес; эски сабактар жарактуу. Конструктордо мугалим белгилейт, китепкананын жаңы 5E
көчүрмөлөрүндө негизги көндүмдөр бар. Базадагы эски сабактар автоматтык өзгөрбөйт.
Карта учурдагы уруксат берилген жооптордон серверде эсептелет; жаңы таблица же кеңири укук талап кылынбайт.
Бир сабак+блок кайра дайындалса бир далил: `answers.updated_at` боюнча акыркы жооп тандалат.
Акыркы үч далилде ката же бир нече аракет болсо «Кайра машыгуу керек»; болбосо эки башка сабактан
биринчи аракетте туура далил болсо «Аткаруу далили бар»; калганы «Далил аз».
Ачык жооп «Мугалимдин текшерүүсү керек» деп көрсөтүлөт, туура жооп деп саналбайт.
Ишеним шкаласы далил эмес. Карта жардам колдонгонун аныктабайт жана өз алдынча өздөштүрүү/баа тууралуу чечим чыгарбайт.
Окуучуга суроонун туура жообу же башка окуучунун маалыматы чыгарылбайт; далил өз тапшырмасына гана байланышат.
Мугалимде далил окуучунун жооп деталдарына байланышат. Учурдагы карта экранда гана, бир барактык PDF форматы өзгөрбөйт.

## Мугалимдин пикиринен кийин кайра иштөө

`answer_revisions` өзүнчө тарых: мугалим оригинал жоопту баалагандан кийин өтүнүч ачат.
`open` + `rubric` гана, 1–3 индексиндеги бөлүктөрдө; Discover, Exit жана `lockOnSubmit` жооптору ачылбайт.
Ар бир өтүнүч суроону, критерийлерди, мурунку жоопту жана пикирди көчүрмө катары сактайт.
Окуучу оңдолгон текстти бир жолу тапшырат; өзгөрүүсүз жооп кабыл алынбайт. Мугалим критерийлер менен кайра
баалайт. Ошондон кийин керек болсо кийинки өтүнүч ачылат; анын мурунку жообу — акыркы оңдолгон жооп.
Бир тапшырмада бир гана активдүү өтүнүч болот. Кийин критерийлер өзгөрсө, эски аракет өз көчүрмөсүн сактайт.
Окуучу `/student/revisions` бетинен өз тарыхын гана көрөт; мугалим классынын дайындоо барагынан башкарат.
Жандуу сабакта пауза жана ачылган бөлүк чеги сакталат. Класстан чыккан окуучу оңдолгон жооп жаза албайт.
`answers`, `attempts`, Exit упайы, XP жана монета бул агымда өзгөрбөйт. Көндүм картасынын автоматтык
жыйынтыгына оңдолгон жооп азырынча кошулбайт: мугалимдин кайра баалоосу өзүнчө далил катары көрүнөт.
0011 миграциясы: RLS + SELECT гана; үч RPC ролду/классты текшерип, сапты кулпулап атомардык иштейт.
Локалдык тест: `supabase/tests/answer_revisions.sql` (өзүнчө тест базасында гана).

## Аралык кайталоо (0012)

План сабактын content’ине эмес, класска дайындоого байланыштырылат: мугалим ар дайындамага өзүнчө бекитет.
`spaced_review_plans.rounds` — үч раунд: `{days, questions:[{prompt,options,correct,explain}]}`.
Ар биринде так үч суроо, 2–4 кайталанбаган вариант жана бир туура индекс; тогуз суроонун тексттери башка.
Күндөр өсүүчү тартипте, 1–90. Демейки 1/3/7 — өзгөртүлүүчү баштапкы график, окуунун универсалдуу оптимуму эмес.
Жарыяланган план өзгөрбөйт, мугалим токтотуп/кайра ача алат. Баштапкы сабакты бүткөн азыркы класс мүчөлөрү гана өтөт.
Биринчи ачылуу = finished_at + days[0]; кийинкиси = max(finished_at + days[i], мурунку кайталоо тапшырылган убакыт + days[i]-days[i-1]).
Мурунку раунд тапшырылбаса кийинкиси ачылбайт. Кеч тапшырган окуучуга бардык раунд дароо ачылбайт.
Окуучуга план таблицасы түз берилбейт. `spaced_review_tasks()` келечектеги суроолорду, тапшырганга чейинки
correct/explain’ди чыгарбайт; туура жооптор ошол раунд тапшырылгандан кийин гана кайтарылат.
`submit_spaced_review` сервер убактысын, мүчөлүктү, планды, жоопторду жана мурунку раундду текшерет;
attempt саптын кулпусу бир учурдагы тапшырууларды иреттейт, ага эч нерсе жазбайт. Натыйжа серверде эсептелет.
`spaced_review_runs` — бир раундга бир гана жыйынтык. Жоопту кийин алмаштырууга жол жок.
Кайталоо баштапкы answers/attempts, XP/монета жана чейректик бааны өзгөртпөйт. Көндүм картасына азырынча кошулбайт.
Мугалим суроо боюнча жоопторду жана каталарды көрөт. Окуучунун бетинде акыркы 50 активдүү план,
мугалимде акыркы 300 тапшыруу көрсөтүлөт. План токтотулса тарых сакталат, окуучунун тизмесинен убактылуу жашырылат.
Жаңы жыйынтыктар үчүн мугалим баракты жаңыртат; окуучунун күтүү барагы көрүнүп турганда мүнөт сайын жаңыланат.
Биринчи версияда тест түрүндөгү кайталоо гана: ЖИ генерациясы, ачык жооп жана автоматтык билдирүү кошулган эмес.

## Класстын далилдер панели

Мугалимдин дайындоо барагындагы `classInsights` учурдагы класс мүчөлөрүнүн ошол сабактагы жоопторун гана топтойт.
Жооп жоктугу ката эмес: бөлүк ачыла элек жана бөлүк ачылган/жооп жок өзүнчө саналат.
Бааланган блокто туура жооп/кайра аракет/ката көрсөтүлөт. Ачык жооп мугалим текшергенче бааланбайт;
критерийлердин баары аткарылса аткарылган далил, айрымдары аткарылбаса кайра машыгуу белгиси.
Эң чоң revision_no’луу оңдоо негизги жооптун баалоосунан артыкчылык алат: requested — оңдоо суралган,
submitted — мугалимдин текшерүүсүн күтөт, reviewed — ошол аракеттин критерийлери боюнча.
Көндүмдө бир окуучу бир жолу саналат: жардам/машыгуу > текшерүү > аткарылган далил артыкчылыгы.
Класстык сунуш үчүн кеминде 3 жооп жана алардын 40%ында кыйындык белгиси керек. Бул продукт эрежеси,
илимий өздөштүрүү чеги эмес; топ үч артыкчылыктуу тапшырманы гана сунуштайт. Аз жоопко класстык жыйынтык жок.
Тестте акыркы тандалган варианттардын саны көрсөтүлөт; алардын себебин ЖИ же алгоритм өз алдынча аныктабайт.
Кошумча ачык жооп жана ишеним шкаласы жетишкендикке кошулбайт. Ар бир окуучунун далилине шилтеме бар.
Сунуш тапшырманы/бааны автоматтык өзгөртпөйт. Мугалим кайталоо планын өзү бекитет.
Бардык булактар толук жүктөлбөсө панель ката көрсөтөт. Учурдагы RLS кардары колдонулат, жаңы укук/таблица жок.

## Үч варианттуу кошумча практика (0013)

Практика сабактын блокторун алмаштырбайт: класска дайындоого байланышкан өзүнчө `pathway_plans` планы.
Бир максат, `support/core/challenge` үч башка тапшырма, баарына бирдей жаңы өз алдынча суроо жана 2–5 критерий.
План бекитилгенден кийин мазмуну өзгөрбөйт; мугалим токтотуп/кайра ача алат.
Демейки вариант — негизги. Мугалим негизги сабакты ачкан азыркы класс мүчөсүнө өзүнчө вариант тандайт.
Окуучуга практика current_stage>=3 болгондо гана ачылат; жандуу пауза жана max_stage чеги сакталат.
Окуучу жардам сурайт, бирок өз вариантын алмаштыра албайт. Мугалим жооп тапшырылганга чейин тандай алат.
Негизги чечим жана жаңы мисалдын жообу чогуу бир жолу тапшырылат. Мугалим эки далилди критерий менен
бир жолу баалайт. Өз алдынчалык автоматтык ырасталбайт. Бул туруктуу окуучу деңгээли эмес.
`pathway_work` тарыхында тандалган вариант, эки жооп жана мугалим пикири сакталат. Биринчи версияда
бир планда бир гана жооп бар, тапшыргандан кийин вариант жана жооп өзгөрбөйт; жаңы кайра аракет агымы жок.
Мугалимдин тандоосу жана окуучунун тапшыруусу attempt сапты кулпулайт. Кардар көрсөткөн вариант учурдагы
сервер тандоосуна дал келбесе жооп четке кагылат; демек терип жатканда мугалим өзгөртсө, жаңы шартты окуу керек.
Окуучуга башка варианттар/башка окуучулардын иштери берилбейт, план таблицасы мугалимге гана жеткиликтүү.
Учурдагы класстын мүчөлүгү жана ролдор RPCде текшерилет; таблицаларга түз жазууга уруксат жок.
Эки жооп тең негизги answers/attempts, Exit упайы, XP жана монетаны өзгөртпөйт; көндүм картасына азырынча кошулбайт.
Окуучунун бетинде акыркы 50 активдүү план көрсөтүлөт. Терилген жооп күтүүсүз жоголбошу үчүн автоматтык
жаңылоо жок; мугалим өзгөрткөндөн кийин окуучу баракты өзү жаңыртат. Долбоордо ЖИ генерациясы жок —
варианттардын бир максатка дал келерин, колдоо көлөмүн жана өз алдынча жаңы мисалды мугалим текшерет.

### Изилдөөдө кадамдык машыктыргыч

`investigation.simulation` — милдеттүү эмес `"condition" | "loop"`. Конструктордо «Кадамдык машыктыргыч» аркылуу тандалат.
Божомол бекитилгенден кийин гана даяр модель ачылат: `condition` жашты 18 менен `>`/`>=` салыштырат,
`loop` 1ден nге чейинки жыйындыны көрсөтөт (n: 0–8). Кошумча `code` мурдагыдай өзүнчө Python редакторунда аткарылат;
модель ошол кодду чечмелебейт. Эски сабактарда бул талаа жок болсо интерфейс өзгөрбөйт.

Бул учурда машыктыргыч экинчи божомол же өзүнчө жыйынтык сурабайт. Окуучу блоктун жалпы `prediction`,
`observations`, `conclusion` жоопторун сактайт; алгачкы божомол серверде өзгөрбөйт. Сынаган маанилерин байкоого жазат.
Параметрлер, басылган кадамдар жана модель чыгышы жоопко автоматтык сакталбайт. Кадамдарды аягына чейин басуу
бөлүктү бүтүрүүгө жетишсиз: мурункудай үч жазуу талап кылынат. Өзүнчө баа же XP берилбейт.

## Жуп/топтун жалпы иш мейкиндиги (0014)

Бул `Block` түрүн алмаштырбайт. Учурдагы `collaboration`/`teamwork` нускамалары сакталат;
мугалим дайындаманын «Жуп жана топ иштерин уюштуруу» бетинде өзүнчө кошумча жалпы тапшырма түзөт.
Бир окуучу бир дайындамада бир топко кирет. Курамы, 2–6 ролу жана тапшырмасы түзүлгөндөн кийин өзгөрбөйт.
Кирүү бөлүгү 1 (Изилдөө) же 3 (Колдонуу); негизги аракеттин прогресси, жандуу сабактын ачылган бөлүгү
жана паузасы серверде текшерилет. Бул ишти аткаруу негизги сабактын прогрессин/баасын/монетасын өзгөртпөйт.

- `team_spaces`: жалпы жооп, активдүүлүк, айлануу, версия, бекитилген убакыт.
- `team_members`: дайындамада кайталанбаган мүчөлөр жана баштапкы слот.
- `team_versions`: түзүү/сактоо/ролду алмаштыруу/бекитүү/токтотуу/кайра ачуу тарыхы.
- `team_notes`: жалпы жооптон кийин ар окуучунун жеке түшүндүрмөсү жана салымы; бир жолку тапшырылат.

Таблицаларда RLS бар; түз INSERT/UPDATE/DELETE жок. Түз SELECT өз классынын мугалимине гана.
Окуучу `my_team_spaces()` аркылуу өзүнүн учурдагы класстагы тобун, ачылган ишти, акыркы беш версияны
жана **өзүнүн гана** жеке түшүндүрмөсүн алат. Топтошунун жеке жообу берилбейт.
Жеткиликтүү акыркы 20 иш көрсөтүлөт. Мугалим дайындамага 50гө чейин топ түзөт.

RPC: `create_team_space`, `change_team_space`, `submit_team_note`, `my_team_spaces`.
Жазууда топтун сабы кулпуланат жана кардардагы версия салыштырылат. Жалпы жоопту учурдагы жазуучу гана
сактайт/бекитет. Мугалим ролдорду айлантып, кийинки жазуучуну тандайт. Бекитилген жалпы жооп өзгөрбөйт;
ошондон кийин жеке түшүндүрмө ачылат. Класстан чыккан окуучу жазуучу катары эсептелбейт жана ишке кире албайт.

Бир учурдагы редактор/Realtime жок: өзгөртүүнү көрүү үчүн кол менен жаңыртуу керек.
Кагылышууда жана башка катада талаалар тазаланбайт; жаңыртуудан мурун жазылган текстти көчүрүп алуу керек.
Жалпы жооптун жыйынтыгы жеке өздөштүрүүнү далилдебейт, автоматтык баалоо жок.

## Түшүндүрмө презентациясы

`presentation`: `title`, `slides` (5–6). Ар слайд: `title` (150 белгиге чейин), `body` (600), `icon` (`idea/computer/table/check`), `diagram` (2–4 текст белгиси, ар бири 80), `question` (300, бош болсо көрсөтүлбөйт). HTML/URL/аткарылуучу код жок; иконка жана кадамдык схема ишенимдүү React/SVG компоненттери менен көрсөтүлөт. Схеманын тексти экран окугучка да жеткиликтүү.

Конструктордо кошулат/түзөтүлөт, ЖИ формасында өзүнчө тандалат. Түшүндүрүү (`practice`) бөлүгүнө гана жарыяланат. 5Eде окуучунун өз түшүндүрмөсүнөн кийин ачылат. Мурунку/кийинки баскыч жана фокус слайд бөлүгүндө турганда ←/→ иштейт; сабак бүткөндө да барактоого болот. Жооп, XP же монета талап кылынбайт; слайддарды көрүү өздөштүрүүнүн далили эмес.

Биринчи версияда мазмундуу иконка жана тексттик схема бар; сүрөт жүктөө, ЖИ bitmap иллюстрациясы, файлга экспорт жана слайддарды каалаганча иреттөө али жок. Эски сабактар өзгөрбөйт. Мугалим долбоордун мазмунун текшерип жарыялайт.

### Слайддагы сүрөт

`slides[].image? = {src, alt, caption, credit}`. `src` — 100 КБга чейинки PNG/JPEG/WebP base64 data URL, белгилүү файл башы текшерилет; тышкы URL, SVG жана HTML кабыл алынбайт. Бул толук антивирус/растр декодер текшерүүсү эмес. Браузер сүрөттү ачып, туурасы/бийиктигин 4096га чейин чектейт. `alt/caption/credit` ар бири 300 белгиге чейин, жарыялоодо `alt` бош болбойт. Жалпы сабак JSON'у 850000 байттан ашпайт. Чоң сүрөттөргө өзүнчө Storage версиясы кийин керек.

Сүрөт FileReader менен тандалып, алдын ала көрүнөт; «Слайдга колдонуу» менен гана редактордун сактоо агымына кошулат. Эски сүрөт жаңысын колдонгонго чейин сакталат. Сүрөттөр сабактын JSON мазмунунда, ошол сабактын учурдагы окуу укуктары менен сакталат. Жаңы ачык bucket/тышкы tracking URL жок. ЖИ сүрөт генерациясы али жок.

### Автоматтык ЖИ иллюстрациясы

Презентация тандалганда тексттик 5E долбоору текшерилгенден кийин Images API аркылуу ар слайдга бир сүрөт суралат (5–6 сурам, бир учурда эки). Модель сервердеги `OPENAI_SLIDE_IMAGE_MODEL` менен жөндөлөт; демейки `gpt-image-2.5-flare`. Тема/класс/слайддын түшүнүгү гана жөнөтүлөт; окуучулардын жооптору жана кол менен жүктөлгөн сүрөттөр жөнөтүлбөйт. Текст/сан жазылбаган иллюстрация суралат, бардык окуу тексти HTMLде калат.

Ар сурам 45 секунд менен чектелет, автоматтык кайра акы төлөнүүчү аракет жок. Алынган растр серверде sharp аркылуу эң көп 640×480 WebPге кичирейтилип, 100 КБ чегинен өтсө гана кошулат. Слайд аталышы alt катары, «ЖИ менен түзүлгөн иллюстрация» булак катары сакталат. Мугалим alt/мазмунду текшерип түзөтөт. Мазмундун тууралыгы автоматтык ырасталбайт.

Айрым/бардык сүрөттөр түзүлбөсө слайддардын схемалары жана сабак сакталат, `warning`, мугалим нускамасы жана генерация тарыхындагы билдирүү аркылуу сан көрсөтүлөт. Чийки тексттик долбоор сүрөт чакыруусуна чейин тарыхта сакталган. Сабак түзүү барагынын maxDuration=300; Images API үчүн өзүнчө уруксат/баланс талап кылынышы мүмкүн. Жаңы миграция жок; сүрөттөр мурункудай сабак JSON'унда.

2026-10-25 көрүнүш оңдоосу: мугалимдин алдын ала көрүүсүндө Түшүндүрүүнүн бардык блоктору жооп жазбастан ачылат. Окуучуда алгачкы түшүндүрмө суроосу сакталат, бирок презентация бар экени жана «Презентацияны көрүү» баскычы көрүнөт; бул баскыч слайддарды жоопко чейин ачат. Толук текст жооп жөнөтүлгөндөн кийин ачылат. Баскыч жооп, XP/монета же бөлүктүн бүтүшү катары эсептелбейт. Эски/презентациясы жок сабактарга слайд автоматтык кошулбайт.

## Дал келтирүү жана жалпы кадам иреттөө

`matching`: `{id,type:"matching",prompt,pairs:[{left,right},…],explain?,xp?}`. 3–8 уникалдуу жуп; туура байланыштар автордун бир саптагы left/right маанилери менен берилет. Окуучуга right өзүнчө туруктуу аралаштырылат. Жооп `{picks:[экрандагы_оң_варианттын_индекси,…]}`; ар сол сапка бирден вариант, кайталоо жок.

`ordering`: `{id,type:"ordering",prompt,steps:["биринчи","экинчи","үчүнчү",…],explain?,xp?}`. 3–8 уникалдуу кадам автордо туура иретте сакталат. Окуучуга аралаш көрсөтүлөт. Жооп `{order:[экрандагы_индекс,…]}` — толук пермутация. Python саптары үчүн мурдагы `parsons` сакталат.

Бул эки түр Колдонуу (`reinforce`) жана Баалоо (`exit`) бөлүктөрүндө колдонулат. Сервер экрандагы индекстерди баштапкы индекстерге которуп текшерет; окуучуга баштапкы индекстер жана туура жооптор тапшырылганга чейин берилбейт. Кардарга кайтарылган жоопто экрандагы тандоо сакталат. Практикада ар позициянын туура/ката белгиси жана кайра аракет бар; түшүндүрмө туура аткаргандан кийин ачылат. Exit'те позициялык кеңеш жана түшүндүрмө жок, бир жооп гана кабыл алынат. Жеке сабакта Exit үчүн unique insert, жалпы таймерде snapshot текшерген атомдук RPC параллелдүү жооптун басып кетишин токтотот. Мурунку Exit жооптор кайра жазылбайт.

XP практикада серверден кайра эсептелет жана бир блокко бир жолу эсептелет; Exit'те бул блокторго XP берилбейт. Жаңы интерактивдер Exit score/total'га MCQ менен катар бир тапшырма = бир упай болуп кирет. Бөлүк бүтүшү/таймердин укуктары мурдагы жалпы эрежелерге баш иет. Оюн аяктоо өзүнчө расмий чейректик баа эмес.

Конструктордо кол менен жана «ЖИ сунушун түзүү» аркылуу кошулат. Толук ЖИ сабагында «Колдонууга дал келтирүү, Баалоого кадамдарды иреттөө» белгиси демейки тандалат; мугалим өчүрө алат. Тандалганда Колдонууга matching кошулуп, Exit'теги үчүнчү MCQ ordering менен алмашат. Эски сакталган сабактар автоматтык өзгөрбөйт. ЖИ мазмунун, жуптардын бир маанилүүлүгүн жана кадамдардын жалгыз туура иретин мугалим текшерет.

Үлгү: `/lab/interactive` — аккаунтсуз, браузерде текшерилет, жооп/сыйлык сакталбайт. Бул чыныгы сервердик агымдын ордуна жүрбөйт.

## Колдонуудагы миссия

Колдонуу (`reinforce`) бөлүгүндө кошумча `mission: {title, story, goal, challengeId}` болот. Ар текст 1–2000 белги. Бул жаңы блок түрү эмес: ошол бөлүктөгү 2–5 милдеттүү интерактив тапшырманы бир окуяга бириктирет. Тизмедеги ирет сакталат; акыркы интерактив — challengeId көрсөтүлгөн, `lockOnSubmit:true`, жеке, милдеттүү, кеминде эки критерийи бар `open`. Ишеним шкаласы миссия кадамы болбойт. Башка бөлүктөрдөгү тапшырмалар өзгөрбөйт.

`missionAllows` серверде да текшерилет: кийинки кадамга чейинки бааланчу тапшырма туура, ачык жооп тапшырылган, изилдөө болсо үч талаасы толтурулган болсун. Жөн гана басуу же туура эмес жооп кийинки кадамды ачпайт. Катада түзөтүп кайра аракет бар. Миссиянын тексттик/көрсөтмө блоктору жооп талап кылбайт. Жалпы таймердин бөлүк чектөөсү миссиядан жогору турат; убакыт бүтүшү миссияны автоматтык бүтүрбөйт.

Акыркы жеке иште платформа ЖИ жардамчысын серверден да өчүрөт; support/extension/feedback/feedbackCode студенттик мазмундан жана жооптон кийин кайтарылган блоктон алынат. Мугалим үчүн түпнуска сакталат. Жеке жооп бир жолу жазылат: unique insert же таймердин атомдук snapshot RPCси параллелдүү басып кетүүнү токтотот. Кайра тапшыруу негизги жоопту өзгөртпөйт; мугалим кайра иштөө агымын ачат. Башка сайттан/түзмөктөн жардам колдонулбаганын платформа далилдей албайт.

Жеке ачык жооптун is_correct=null, миссия панели «тапшырылды — мугалим карайт» дейт. Миссияны тапшыруу өздөштүрүү, расмий баа же өзүнчө монета берчү окуя болуп эсептелбейт. Мурдагы сабак прогресси/сыйлыгы жана критерий менен мугалим баалоосу колдонулат. Акыркы жеке суроону мурдагы машыгуудан башка кырдаалга түзүү жана далил талап кылган критерийлерди кароо мугалимдин милдети.

Конструктордо «Колдонууну миссия кылуу»: акыркы ылайыктуу жеке ачык жооп бекитилет же жаңы жеке иш кошулат. Жаңы машыгуу автоматтык жеке иштен мурда кирет. Өчүрүү миссия каркасын гана алат, тапшырмаларды өчүрбөйт; жеке иштин lockOnSubmit белгиси кол менен өзгөртүлөт. Жеке ишти алып салуу/акыркы орундан жылдыруу же милдеттүү тапшырманы 5тен ашыруу миссияны жараксыз кылат; сактоо/жарыялоо текшерүүсү билдирүү берет. Сакталган эски сабактарга миссия өзүнөн-өзү кошулбайт.

Толук ЖИ формасында «миссия» тандалса интерактив да кошулат; JSON схема миссиянын окуясын/максатын талап кылат. Сервер туруктуу block ID жана акыркы жеке ишти өзү бекитет. ЖИ сунушун мугалим текшерет; мааниси боюнча жаңы кырдаал экенине автоматтык кепилдик жок. ЖИ оңдоо панелинде миссиянын аталышы/окуясы/максаты да тандалат.

`/lab/mission` — серверге жооп сактабаган, акысыз браузер үлгүсү; сервердик агымдын жана чыныгы класстагы пилоттун ордуна жүрбөйт. Жаңы миграция талап кылынбайт: миссия lesson JSON ичинде, жооптор мурдагы answers таблицасында.

## Электрондук таблица (`spreadsheet`)

`{id,type:"spreadsheet",prompt,rows,columns,initialCells,locked,checks,xp?}`. 3–12 сап, 3–8 мамыча (A–H), ар уячага 200 белгиге чейин, жалпы 96 уяча. `initialCells: {A1:"Товар",B2:"4",…}`; `locked:["A1","B2",…]` — окуучу өзгөртө албаган уячалар. `checks:[{cell:"D2",expected:"=B2*C2",formula:true},…]` — 1–8 уникалдуу текшерүү; текшерилчү уяча бекитилбейт. Мугалимдин күтүлгөн формуласы эсептелбесе сактоо четке кагылат. Баштапкы жыйынтык уячаларын бош калтырып, окуучуга тапшырманы жана даректерди так жазыңыз.

Диалект: сан, текст, = менен башталган формула; + - * /, кашаа, unary +/-, A1/$A$1 шилтемелери, SUM/AVERAGE/MIN/MAX, A1:B3 диапазондору, үтүр/чекиттүү үтүр менен аргумент. Ондук чекит; бош уяча 0; диапазондогу текст суммадан/орточодон чыгарылат. Нөлгө бөлүү, айлампа, чекке батпаган шилтеме жана белгисиз функция түшүнүктүү ката берет. Excelдин бүтүндөй функцияларын, макрос/JS, файл импортун, график/форматтоону камтыбайт. Формула eval/Function аркылуу аткарылбайт; грамматика, клетка өлчөмү, рекурсия жана операция саны чектелген.

Студенттик мазмунда expected дайыма бош, checksHidden=true. Уяча дареги жана формула талабы көрүнөт. `response:{cells:{D2:"=B2*C2",…}}` серверге берилет; passed/is_correct кардардан алынбайт. Сервер өлчөм/дарек/бекитилген уячаларды текшерип, өзү кайра эсептейт. Ар expected формула бардык автордук checks коюлган эталон торчодо эсептелет. Formula=true болгондо окуучунун мааниси = менен башталсын жана баштапкы сандык кириштер (же сандык маани талап кылынган check уячалары) +3 жана ×2+1 болуп бирден өзгөргөндө да эталонго дал келсин. Бул альтернативдүү эсептөө жолдорун кабыл алат жана даяр сан/=320 сыяктуу жоопту көпчүлүк шилтеме тапшырмаларында токтотот; чектелген мисалдык текшерүү универсалдуу математикалык эквиваленттүүлүк далили эмес.

Колдонууда ката уячалары белгиленип, кайра аракет бар; XP кайра эсептелип бир блокко бир жолу кошулат. Баалоодо бир жолу жооп, positions жок; unique insert/жалпы таймердин snapshot RPC коргоосу сакталат. Exit score/total'га бир блок = бир тапшырма болуп кирет. Миссиянын машыгуусу боло алат; акыркы жеке миссия иши мурдагыдай өзүнчө ачык түшүндүрмө. Сыйлык/таймер өздөштүрүү катары чечмеленбейт.

Уяча басылып, жогорудагы маани/формула талаасынан оңдолот; таблица өз контейнеринде туурасынан жылат. Черновик аракет/блок боюнча localStorage'да, тапшырылган толук cells жоопто сакталат; башка түзмөккө черновик көчпөйт. Кайра ачканда мугалим бекиткен уячалар учурдагы тапшырмадан алынат. Мугалим отчетто окуучунун уячаларын жана формулаларын көрөт. Схемада жаңы таблица талап кылынбайт.

Конструктор баштапкы маалымат/өлчөм/locked/checks'ти оңдойт. Өлчөм кичирейсе сырттагы маалымат алынып салынат. ЖИ оңдоо аркылуу блок кошулат, толук ЖИ формасында таблица тандалса 6×4 cells матрицасы жана checks түзүлүп, сервер block ID'ни коёт. Миссия тандалса жеке иштен мурда кошулат. Мугалим шарттын, формуланын жана окуу максатынын шайкештигин текшерет. Эски сабактар автоматтык өзгөрбөйт.

`/lab/sheet` — аккаунтсуз браузер үлгүсү; черновик ошол браузерде сакталат, кайра баштоо аны тазалайт. Бул үлгүнүн текшерүүсү серверге жыйынтык сактабайт жана чыныгы мугалим–окуучу пилоту болуп эсептелбейт.

## Категорияларга бөлүштүрүү (`classification`)

`{id,type:"classification",prompt,categories:["Киргизүү","Чыгаруу",…],items:[{text:"Клавиатура",category:0},…],explain?,xp?}`. 2–5 уникалдуу категория, 3–12 өзүнчө объект; category — нөлдөн башталган бүтүн индекс. Бир категорияга бир нече объект кирет. Ар категория кеминде бир объект менен колдонулат; объекттин жалгыз так туура тобу болушу керек. Эки маанилүү/бир нече топко кирчү мисалды мугалим тактайт. Prompt/explain 3000, категория аты 120, объект тексти 300 белгиге чейин; XP 0–100. Колдонуу жана Баалоо үчүн гана.

Окуучуга объекттер аракет/блок боюнча туруктуу аралаштырылып, category=-1 жана shuffled=true менен берилет. Туура категориялар эч качан студенттик блокто ачылбайт; explain практикада туура аткаргандан кийин гана берилет, Баалоодо берилбейт. Жооп `{groups:[категориянын_индекси,…]}` — экрандагы ар объектке бирден тандоо. Сервер аны баштапкы объекттердин иретине которуп баалайт, андан кийин жооп жана практикадагы positions кайра экрандын ирети менен сакталат. Ошентип баштапкы объект индекси/иреттен туура жооп чыкпайт. Бош, кыска, sparse, сап түрүндөгү же чектен тыш индекс кабыл алынбайт.

Практикада позициялык пикир жана кайра оңдоо; Баалоодо бир жооп, positions/ЖИ жардамчы/түшүндүрмө жок. Жооп unique insert же жалпы таймердин атомдук RPCси менен сакталат. Ар бир объектке туура категория тандалганда бүт блок туура болуп эсептелет; жарым-жартылай упай азырынча жок. XP практикадагы бир блокко бир жолу эсептелет, Exit жыйынтыгында бир блок = бир тапшырма. Ишеним/билим сапаты автоматтык расмий баа болуп эсептелбейт.

Конструктор категорияларды, объекттерди, туура топторду жана түшүндүрмөнү оңдойт. Категориянын иретин өзгөртүү индекстердин маанисин өзгөртөт — объекттердин туура топторун кайра текшериңиз. ЖИ оңдоо панелинде ушул түр кошулат, текст/категория аттары өзүнчө оңдолот. Толук ЖИ формасында тандалса Колдонууга 2–4 категория/4–8 объект түзүлөт; сервер форматты текшерет, мугалим мазмундун тууралыгын бекитет. Миссияда машыгуу катары, акыркы жеке иштен мурда кошулат. Эски сабактар өзгөрбөйт; жаңы база миграциясы жок.

Тандоо native select аркылуу иштейт: сүйрөө талап кылынбайт, басуу/клавиатура бар. «Сен түзгөн топтор» тандоонун учурдагы көрүнүшүн берет; бул туура жооптун ачылышы эмес. Черновик аракет/блок боюнча localStorage'да; тапшырылган жана бекитилген жооп сервердин кабыл алган тандоосун көрсөтөт. `/lab/classification` аккаунтсуз үлгүсү браузерде гана текшерилет, жооп/монета базага сакталбайт.

### Практикалык жооптун далили

matching/ordering/classification/spreadsheet жоопторунда сервер `response.task` версия 1 көчүрмөсүн сактайт. Анда окуучуга көрүнгөн объекттер/варианттар көрсөтүлгөн иретте же таблицанын өлчөмү/текшерилген уячалар бар. Туура категория картасы, туура жуптардын байланышы жана эталон формулалар көчүрмөгө кирбейт. Мурда туура тапшырылган жоопту кайра жөнөтүү анын көчүрмөсүн алмаштырбайт.

Мугалимдин класстык талдоосу жана жеке отчету тандоолорду ушул аттар менен чечмелейт. Көрүнгөн мазмун азыркы сабакка дал келгенде гана учурдагы эталон кошулат. Эски жоопто көчүрмө жок болсо, азыркы мазмун колдонулганы эскертилет. Бул көрүнүш мурда сакталган бааны же аракет санын өзгөртпөйт. Таблицадагы формулалар сакталган уячалар менен эсептелет; формуланын эквиваленттүүлүгү отчетто кайра бааланбайт. Окуучунун кыска отчетуна бул мугалимдик маалымат берилбейт.

### ЖИ сабагындагы көндүмдөр

Толук сабак түзүү схемасы `skillTags` объектин талап кылат: explore/explain/application/pairTask/groupTask/exit1/exit2/exit3/reflection жана тандалган applicationGame/exitGame/sheet/classification үчүн `SKILLS` тизмесинен 1–3 кайталанбаган ID. Сервер белгилерди өзү түзгөн блок IDлерине көчүрөт; белгисиз/ашык/жетишпеген талааларды жана бузук тизмени четке кагат. Колдонулбаган жуп/топ же алмаштырылган exit3 блогуна далил кошулбайт. Кызыктыруу, текст, презентация жана ишеним шкаласы автоматтык белгиленбейт.

Жаңы көндүмдөр: `spreadsheets` — электрондук таблица жана формулалар; `information` — маалыматты уюштуруу жана классификациялоо. Конструктордо мугалим белгилерди өзгөртөт/алып салат. Белги автоматтык баа эмес; жооптун учурдагы текшерүү эрежеси сакталат. Биринчи аракеттин тууралыгы жардамсыз аткарылганын далилдебейт. Эски сабактарга белгилер артка карай кошулбайт; мурдагы генерация жообу `skillTags` жок болсо да ачылат. ЖИ менен тандалган жерди оңдоодо жаңы көндүмдү автоматтык сунуштоо бул кадамга кирбейт.

### КТПдеги көндүмдөр жана иштер

KtpTopic жана KtpSession кошумча `skills?: SkillId[]` (0–3 кайталанбаган ID), `kind?: lesson|practical|quarterly`, `quarter?: 1|2|3|4`, `product?: string` талааларын колдойт. Сериядагы сабак skills/kind/quarter жок болсо темадан мурастайт; `skills:[]` атайын бош тандоо. Сабактын өз product талаасы милдеттүү жана теманыкын алмаштырат. Бул метадата учурдагы `ktp_plans.sections` JSON ичинде, жаңы миграциясыз жана мурунку мугалим ээлиги/RLS менен сакталат.

7–8-класстын 100 темасына көндүмдөр жана 19 практикалык ишке продукт сунушталды. Ар класска төрт чейректик сунуш сааты бөлүнбөгөн бөлүмдө көрсөтүлөт. Түпнуска 68 саат/темалар сакталат; мугалим чейректерге чындап өтүлгөн мазмунду жана сааттарды өзү ылайыкташтырат. Бул расмий чейректик бааны эсептөө эмес. Көндүмдөрдүн педагогикалык кароосу: `docs/KTP_SKILLS_AUDIT.md`.

Эски мугалим пландары автоматтык өзгөртүлбөйт. «Көндүмү жок темаларга сунуш кошуу» так аталышы дал келген, skills жок темаларга гана толтурат; [] жана мугалим тандаган белгилер/саат/серия сакталат. Чейректик иштерди кошуу бир чейрекке кайра сунуш кошпойт. `/lab/ktp` ошол эле редактордун базага жазбаган жалпы үлгүсү.

Толук ЖИ сабагынын input.curriculum контексти серверден текшерилген КТПден алынат; kind/quarter/product/skills маалымат катары колдонулат. Кызыктыруу → ... → Exit тартиби сакталат, чейректик иш мазмуну мугалимдин бекитүүсүн талап кылат. ЖИ жаңыдан жазган ар тапшырманын көндүмүн мугалим дагы текшерет.

### Иштин түрү
`activityKind?: "game" | "quarterly"` — оюн же чейректик иш. Жок болсо кадимки сабак. Беш бөлүктүн тартиби сакталат. Оюн чейректик эсепке кирбейт. Чейректик ЖИ долбоорунда практикалык жеке тапшырма Баалоо бөлүгүнө да кошулат; мугалим жарыялоодон мурун текшерет. Дайындоодо окуу жылы/чейрек өзүнчө `assignments` метадайындары менен белгиленет.

Жаңы ЖИ сабак долбоорлорунун Түшүндүрүү бөлүгүндө милдеттүү `presentation` блогу жана так 5 слайд бар. ЖИ JSON схемасында slides дайыма required, minItems=maxItems=5; сервер да санын текшерет. Жалпы формат эски 5–6 слайддык кол менен редакцияланган/сакталган презентацияларды дагы окуйт.
