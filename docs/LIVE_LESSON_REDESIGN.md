# Сабак өтүү: азыркы абалы жана мугалим башкарган жаңы агым

Дата: 2026-11-09. 1–2-этаптар ишке ашты (TASKS.md, 41–42-бөлүмдөр); 3–4-этаптар — пландар.

## 1. Азыр кантип иштейт (коддон)

1. Мугалим сабакты класска жөнөтөт (`assignLesson`) → дайындама түзүлөт → **окуучуга ошол замат көрүнөт** жана ал
   сабакты дароо баштай алат. «Мугалим баштай элек» деген абал жок.
2. Сабак өтүүнүн **үч режими** бар, алар дайындаманын натыйжалар барагынын (`/teacher/assignments/[id]`) башында,
   эки башка формада жайгашкан:
   - **Өз алдынча** (демейки): сессия жок, окуучу бөлүктөрдү өз ылдамдыгы менен ачат.
   - **Жандуу** (`lesson_sessions.max_stage`, 0008): мугалим «ачылган акыркы бөлүктү» тизмеден тандап, «Режимди сактоо»
     баскычын басат. Окуучу ошол бөлүккө чейин гана өтө алат. «Талкуу үчүн токтотуу» деген белги бар.
   - **Жалпы таймер** (0015): бөлүктөр убакыт боюнча өтөт, «Кийинки/Артка/Тыныгуу/+мүнөт» баскычтары бар.
     Ушул режимде гана так бир бөлүк ачык.
3. Окуучу мугалимдин өзгөртүүсүн **сурамдар аркылуу** билет: жандуу режимде барак ар 20 секундда толук жаңыланат
   (`AutoRefresh`), таймер режиминде ар 3 секундда сурам жиберилет. Мугалимдин барагы да ар 3–20 секундда толук жаңыланат.
4. Мугалим көргөн маалымат: бөлүктөр боюнча бүтүргөндөр, exit ticket статистикасы, окуучулардын абалы («жардам керек»,
   «тыгылды»). Булардын баары **сабактан кийинки** талдоого ылайыкталган.

## 2. Кемчиликтер

| # | Көйгөй | Натыйжасы |
| --- | --- | --- |
| 1 | Сабак жөнөтүлгөн замат окуучуга ачылат | Окуучулар сабакка чейин эле баштап, тапшырмаларды үйдө «чечип» коюшат. Кызыктыруу/Изилдөө бөлүктөрүнүн мааниси жоголот |
| 2 | Демейки режим — өз алдынча | Мугалим режимди которууну унутса, класс ар кайсы бөлүктө жүрөт |
| 3 | Үч режим, эки форма, ар башка эрежелер | Мугалимге түшүнүксүз: «max_stage», «таймер», «токтотуу» бири-бирине кантип таасир этери белгисиз |
| 4 | Башкаруу натыйжалар барагынын ичинде | Сабак учурунда мугалимдин көз алдында бөлүшүү картасы, чейрек формасы, статистика турат. Телефондон башкаруу ыңгайсыз |
| 5 | «Активдүү сабак» деген түшүнүк жок | Мугалимдин башкы бетинде жүрүп жаткан сабак көрүнбөйт; сабакты «бүтүрүү» кадамы жок (таймерден башка) |
| 6 | Өзгөртүү 20 секундга чейин кечигет | Мугалим «кийинки бөлүк» деп айтат, окуучулардын экраны дагы деле эски бөлүктө турат |
| 7 | Сурамдар көп (polling) | 30 окуучу × ар 3 сек = секундасына ~10 сурам бир класстан; толук барак жаңыртуу оор |
| 8 | Мугалим «азыр» эмне болуп жатканын көрбөйт | Ким онлайн, ким ушул бөлүктү бүттү («24/28»), азыркы суроого класс кандай жооп берип жатат — жок. Качан өтүү керектигин чечүү кыйын |
| 9 | Талкуу үчүн курал жок | Класстын жоопторун (атсыз) тактага чыгаруу, тестте эмнени көп тандаганын көрсөтүү жок |
| 10 | Сабак бүткөндө эмне болору белгисиз | Келбей калган же бүтүрө албаган окуучулар үчүн «үйдө бүтүрсүн» деген чечим жок |
| 11 | Оюн жалпы таймерде ойнолбойт | Мугалим башкарган сабакта оюн блогу иштебей калат |

## 3. Сунуш: «Сабак сеансы»

Негизги идея (Nearpod, Pear Deck сыяктуу платформалардагы «мугалим башкарат / өз алдынча» эки режим):
**сабактын жашоо цикли** жана мугалим үчүн өзүнчө **«Жандуу сабак» экраны**.

### 3.1. Жашоо цикли

```
Жөнөтүлдү ──[Сабакты баштоо]──▶ Жүрүп жатат ⇄ Тыныгуу ──[Сабакты бүтүрүү]──▶ Бүттү ──▶ (кааласа) Үйдө бүтүрүү
```

- Жөнөтүүдө мугалим тандайт: **«Класста өтөм (мен башкарам)»** — демейки, же **«Өз алдынча / үй тапшырмасы»**.
- **Жөнөтүлдү:** окуучунун тизмесинде сабак «Мугалим баштаганда ачылат» деп кулпуланган карточка болуп турат.
  Ачса — күтүү бөлмөсү (сабактын аты, класс, «Мугалимди күт»).
- **Жүрүп жатат:** мугалим ачкан бөлүк гана активдүү. Окуучу мурунку бөлүктөрүн карай алат, алдыга өтө албайт.
  Мугалим «Кийинки бөлүк» баскан замат бардык окуучунун экраны ошол бөлүккө өтөт (1–2 секунд).
- **Тыныгуу («Тактага карагыла»):** окуучунун экраны жабылат. Талкуу же түшүндүрүү үчүн.
- **Бүттү:** мугалим «Сабакты бүтүрүү» баскычын басканда тандайт: бүтүрө албагандар **үйдө бүтүрсүн** (мөөнөт менен,
  өз алдынча режимге өтөт) же сабак жабылсын.

### 3.2. Мугалимдин «Жандуу сабак» экраны (`/teacher/live/[assignmentId]`)

- **Үстүңкү тилке:** 5 бөлүктүн кадамдары, чоң **«Кийинки бөлүк →»** баскычы, «Тыныгуу», «Артка», сабактын убактысы
  (бөлүктүн `minutes`и — **сунуш катары**, мажбурлабайт; кааласа автоматтык таймерди күйгүзөт).
- **Окуучулар торчосу:** ар бир окуучу — карточка: онлайн/офлайн, учурдагы бөлүктү бүттүбү ✓, жардам керекпи (катары
  менен ката), качан акыркы жооп берди. Жогоруда: **«Ушул бөлүктү 24/28 бүттү»** — өтүүгө даярдыктын көрсөткүчү.
- **Учурдагы бөлүктүн жооптору:** ар тапшырма боюнча жандуу жыйынтык — тестте варианттардын бөлүнүшү, ачык
  жооптордун тизмеси. **«Тактага көрсөтүү»** — атсыз проектор көрүнүшү (талкуу үчүн).
- Телефондон да башкарса болот: астыңкы тилкеде «Кийинки бөлүк» жана «Тыныгуу».
- Мугалимдин башкы бетинде жана каптал менюсунда **«Жүрүп жаткан сабак»** баннери: бир басуу менен ушул экранга кайтат.

### 3.3. Ыкчам байланыш (Realtime)

- Polling'дун ордуна **Supabase Realtime**:
  - **Broadcast** каналы `lesson:{assignmentId}` — мугалим бөлүктү которгондо/тыныгуу бергенде окуучуларга дароо билдирүү.
  - **Presence** — ким онлайн экенин мугалим көрөт.
  - Мугалимдин экраны жаңы жоопторду (`answers`) Postgres Changes аркылуу же 5 секунддук жеңил сурам менен алат.
- Ыйгарым укук ошол эле: абал базада (`lesson_sessions`) сакталат, Realtime — «жаңыртуу керек» деген сигнал гана.
  Окуучу каналга кошулуп калса да, сервер жоопту `liveAllows` менен текшерет. Байланыш үзүлсө 15 секунддук запас
  сурам иштейт.

### 3.3.1. Ишке ашырылганы (2-этап)

- `src/lib/use-lesson-channel.ts`: бир дайындамага бир канал `lesson:{assignmentId}`.
  Postgres Changes (`lesson_sessions`, 0019 жарыялоо) + broadcast `session`/`activity` + presence (ачкыч — колдонуучу id).
- Окуучу: сигнал келсе дароо `pollLessonClock`; туташканда запас сурам ар 15 сек, таймер режиминде мурункудай ар 3 сек
  (автоматтык өтүү сервердеги сурамда эсептелет). Жооп сакталганда мугалимге `activity`.
- Күтүү бөлмөсү: «Баштоо» басылганда дароо ачылат; presence менен мугалим аны онлайн көрөт.
- Мугалим: сигнал келгенде барак 1,5 секундда бир жолудан көп эмес жаңыланат; запас — туташканда 20 сек, болбосо 4 сек.
  Буйрук сакталганда окуучуларга `session` жөнөтүлөт (delete окуясын да камтыйт). «Онлайн N/M» жана ар окуучунун белгиси.
- Каналдар ачык (public): билдирүүлөрдө маалымат жок, абал серверден окулат. Supabase'те «Private channels only»
  күйгүзүлсө канал туташпайт жана бардыгы запас сурам менен иштейт.

### 3.4. Эрежелер

- Мугалим башкарган режимде окуучунун бөлүккө кириши мугалимдин учурдагы бөлүгүнө көз каранды. Мугалим ачканга
  чейинки бөлүктөр жана аткара элек иштер ачык бойдон калат (артта калгандар жетише алат), бирок алдыга өтүүгө болбойт.
- 5E эрежеси (Түшүндүрүүгө чейин ачык жоопту тапшыруу ж.б.) өзгөрбөйт.
- Оюн блогу мугалим башкарган режимде иштейт; таймер режиминдеги азыркы тыюу алынат (абалды version менен сактоо керек).
- Монета, XP, баалоо эрежелери өзгөрбөйт.

## 4. Техникалык схема (сунуш)

Миграция `0018_lesson_delivery.sql`:

- `assignments.delivery text not null default 'class' check (delivery in ('class','self'))`.
  **Эски дайындамалар `self` болуп белгиленет** — алар азыркыдай иштей берет.
- `lesson_sessions`: `status` (`waiting|live|paused|ended`), `started_at`, `ended_at`; `max_stage` — учурдагы бөлүк.
  Мурунку `timed` талаалары кошумча опция болуп калат.
- `start_lesson`, `advance_lesson`, `end_lesson(p_homework_due)` RPC'лери: мугалимдин укугун текшерип, сапты кулпулап,
  версия менен жаңыртат (0015'теги сыяктуу).
- RLS: `delivery='class'` жана `status='waiting'` болсо, `submitAnswer` жана сабактын мазмуну окуучуга берилбейт
  (серверде `liveAllows` кеңейтилет).

## 5. Этаптар

1. **Жашоо цикли жана мугалимдин экраны** — `delivery`, күтүү бөлмөсү, «Сабакты баштоо/Кийинки бөлүк/Тыныгуу/Бүтүрүү»,
   окуучулар торчосу (бүттү/жардам керек), «Жүрүп жаткан сабак» баннери. Байланыш азырынча кыска polling менен.
2. **Realtime** — broadcast + presence; polling запас катары гана.
3. **Талкуу куралдары** — учурдагы бөлүктүн жандуу жыйынтыктары, «Тактага көрсөтүү» проектор режими.
4. **Сабактан кийин** — «үйдө бүтүрүү» агымы, сеанстын отчету; эски үч режимди бир моделге бириктирүү.

Ар этапта: `npm run lint && npm test && npm run build`, SQL тесттер (мугалим/окуучу/башка класс, күтүүдөгү сабакка
жооп берүүгө тыюу), 375px текшерүү.
